# ADPADZ DESIGN SYSTEM

Version 1.0

## PURPOSE

This document defines the visual language of Adpadz.

Every page, component, section, modal, dialog, builder, dashboard, Smart Card, Campaign page, and future feature MUST follow this document.

No page may invent its own visual style.

---

# DESIGN PHILOSOPHY

Adpadz should feel:

Premium

Modern

Interactive

Beautiful

Fast

Confident

Friendly

Local

Never feel:

Corporate

Busy

Template-based

Cheap

Dashboard-heavy

Every screen should feel like it belongs to one product.

---

# DESIGN PRINCIPLES

Business owners should instantly know:

What this page is.

What they should do next.

What action is most important.

Every screen should have one dominant action.

---

# COLOR SYSTEM

Primary Accent

Adpadz Green

Secondary Accent

Adpadz Blue

Neutral

Dark Gray

Light Gray

White

Error

Red

Success

Green

Warning

Amber

Never invent random colors.

---

# TYPOGRAPHY

Only use these levels.

Hero

Page Title

Section Title

Card Title

Body

Caption

Do not create custom font sizes.

---

# SPACING

Use one spacing scale only.

4

8

12

16

24

32

48

64

Never use arbitrary spacing.

---

# BORDER RADIUS

Allowed only:

8

16

24

999 (pill)

---

# SHADOWS

Three shadow levels.

Low

Medium

Floating

Do not invent custom shadows.

---

# BUTTONS

Allowed button variants:

Primary

Secondary

Ghost

Danger

Icon

Large CTA

Every page must reuse AdpadzButton.

Never create custom button styling.

---

# CARDS

Allowed card variants:

Standard

Featured

Glass

Coupon

Flat

Every card extends AdpadzCard.

---

# BADGES

Allowed badge variants:

Campaign

Offer

Verified

Local

Status

Do not create new badge styles.

---

# PILLS

Used for:

Location

Offer

Status

Category

Campaign

Always use AdpadzPill.

---

# ICONS

Icons should always:

Match size

Match spacing

Use consistent stroke

Never mix icon styles.

---

# HERO

Every Hero contains:

Image

Logo

Business Name

Tagline

Primary Badge

Optional Campaign Badge

No oversized overlays.

Never hide important artwork.

---

# ACTION BAR

Action bars are primary navigation.

Use:

Call

Text

Email

Website

Directions

Save Contact

Booking

Keep compact.

No giant button cards.

---

# OFFERS

Offer cards should feel like premium coupons.

Always include:

Offer Badge

Offer Title

Description

CTA

Optional expiration

Optional redemption instructions

Never large empty areas.

---

# SECTIONS

Pages should assemble reusable sections.

Allowed sections:

HeroSection

ActionSection

OfferSection

BookingSection

LeadSection

VideoSection

GallerySection

BeforeAfterSection

TestimonialsSection

LinksSection

FooterSection

Do not create page-specific layouts.

---

# MOTION

Animation should be subtle.

Cards:

Fade

Slide

Offers:

Gentle pulse

Buttons:

Lift on hover

Modals:

Fade

Never use flashy animation.

---

# PAGE STRUCTURE

Every page should follow:

Hero

↓

Primary Action

↓

Primary Content

↓

Supporting Content

↓

Footer

Avoid dashboard stacking.

---

# RESPONSIVENESS

Desktop first.

Tablet optimized.

Mobile excellent.

No horizontal scrolling.

Touch targets minimum 44px.

---

# EMPTY STATES

Every empty state should:

Explain why

Explain what to do

Provide one CTA

Never leave blank pages.

---

# DASHBOARDS

Dashboards should answer:

What needs attention?

What should I do next?

Avoid walls of statistics.

---

# BUSINESS HUB

Business Hub should feel like a command center.

Not an admin panel.

---

# CAMPAIGNS

Campaigns should always feel alive.

Display:

Status

Timeline

Outputs

Performance

CTA

---

# SMART CARD

Business Profile should feel like:

A premium landing page.

Never like a profile form.

---

# COMMUNITY MAILERS

Should feel like:

Campaign distribution.

Not print design software.

---

# QR STUDIO

Should feel like:

Campaign destination management.

Not a QR generator.

---

# FUTURE FEATURES

Every new feature must answer:

Does an existing Design System component already solve this?

If yes:

Reuse it.

If no:

Extend the Design System first.

Never create isolated UI.

---

# CODEX RULES

Before changing any UI:

Read this document.

Reuse existing Design System components.

Reuse existing Section Library.

Do not invent layouts.

Do not invent colors.

Do not invent spacing.

Do not invent shadows.

Do not invent button styles.

If a new visual pattern is required:

Update this document first.

Then implement it.

Never the other way around.
