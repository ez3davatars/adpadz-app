# Adpadz Documentation Index

These documents collectively define Adpadz. They must be interpreted together.

## Governing documents

### Product Vision
`ADPADZ_PRODUCT_VISION.md`

Defines why Adpadz exists, who it serves, the customer experience, and its long-term direction.

Use for:

- New product concepts
- Consumer discovery
- The Pad
- Community
- Strategic product positioning

### Architecture
`ADPADZ_ARCHITECTURE.md`

Defines system boundaries, ownership, data flow, and the Create Once, Publish Everywhere model.

Use for:

- Database decisions
- Feature ownership
- Component relationships
- Campaign outputs
- Avoiding duplicate systems

### Design System
`ADPADZ_DESIGN_SYSTEM.md`

Defines the visual language and reusable interface patterns.

Use for:

- UI work
- Layouts
- Components
- Typography
- Motion
- Responsive behavior

### Decision Rules
`ADPADZ_DECISION_RULES.md`

Defines how product and engineering decisions must be evaluated.

Use for:

- Resolving competing approaches
- Scope control
- Preventing unnecessary complexity
- Reviewing Codex proposals

## System-specific documents

### Mission Control
`ADPADZ_MISSION_CONTROL.md`

Defines internal administration, authorization, security, and staff operations.

### Community Mailer Builder
`ADPADZ_COMMUNITY_MAILER_BUILDER.md`

Defines mailer layouts, placement geometry, permissions, booking, and print limitations.

## Priority when documents appear to conflict

1. Security and data integrity
2. Product Vision
3. Architecture
4. Decision Rules
5. Design System
6. System-specific implementation documentation

Do not silently choose between conflicting instructions. Report the conflict and propose a resolution.
