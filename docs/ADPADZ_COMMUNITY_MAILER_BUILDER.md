# Adpadz Community Mailer Builder

## Architecture

All mailer experiences use `CommunityMailerCanvas` and the same normalized
placement geometry:

- Mission Control: `/admin/community-mailers/:mailerId` in `admin-edit` mode.
- Business Hub: `/app/business/community-campaigns` in `business-review` mode.
- Public booking: `/community-cards/:slug` in `public-booking` mode.
- Browser print preview: the Mission Control detail route in `print-preview`
  mode.

The database columns `side`, `x`, `y`, `width`, and `height` are authoritative
percentages. The renderer does not reconstruct geometry from `slot_key` or
viewport pixels. Historical named layout keys map to the two canonical fixed
templates; unknown keys do not silently fall back to another format when no
persisted rows exist.

The 9x12 format renders at a 12:9 landscape ratio. The 6x11 format renders at an
11:6 landscape ratio. Each format has a separately rendered, protected Adpadz
identity/mailing region so legacy sellable placements are not moved.

## Approved layout catalog

The operator cannot freely drag or resize sellable placements. Each 9x12 side
uses a four-unit top row and a four-unit bottom row. Each row independently
supports four singles, one double at the left/center/right, two doubles, or one
full-width four-unit placement. This provides controlled variation without
arbitrary geometry.

The grid uses a 0.75% outer inset and 0.6% internal gutters, so artwork fills
the card to the bleed-safe edge instead of leaving a large cream border. Front
and back row patterns may be selected independently. The front center band
always includes the postal indicia area; the back center band contains the
Adpadz identity and discovery QR. The compact 6x11 format retains its one
approved fixed grid.

Each fixed placement has a stable `template_index`. Geometry is generated by
the approved template and cannot be mutated through an old client or direct
placement RPC.

Existing freeform 9x12 mailers are explicitly marked `legacy_freeform`. An
operator may convert either side to an approved template only while every
placement on that side is available, unassigned, and has no order history.
This prevents a layout switch from silently moving or deleting sold inventory.

## Canonical placement data

The visual builder keeps the existing normalized geometry and adds:

- placement type and tier;
- z-index;
- price and explicit discount;
- category exclusivity;
- featured, placement lock, and layout lock state;
- business, approved asset, and QR relationships;
- payment, proof, and production state;
- explicit public-creative visibility.

Legacy advertiser names, creative URLs, `mini`, and `adpadz` placement types
remain compatible. Legacy system brand rows are not rendered as sellable
inventory because the protected brand region is rendered separately.

## Save and validation behavior

Choosing **Apply layout** invokes one database transaction. It locks the mailer,
checks authorization and assignment/order history, replaces only safe unused
inventory on the selected side, inserts the six canonical placements, validates
the result, and increments the layout revision.

Campaign settings retain tab-scoped recovery drafts. Placement business,
creative, pricing, payment, proof, and production fields save independently;
template geometry is read-only.

Mission Control's customer preview renders the current browser draft through
the shared public mode, even before a mailer is published. The preview applies
the same creative-visibility rules and does not activate booking actions.

## Security boundary

Community Mailer mutation RPCs require an active `admin_users` role of `owner`
or `admin`. Other active Mission Control roles receive read-only UI and remain
denied by PostgreSQL.

Business and public clients cannot select the raw `community_cards` or
`community_card_slots` tables. The Business Hub RPC returns all geometry with
generic neighboring states, but only returns assignment, creative, QR, payment,
proof, and production details for the caller's own placement. The public RPC
maps internal state to `available`, `occupied`, or `unavailable`; advertiser
identity and artwork appear only when `public_creative_visible` is true.

Authenticated clients cannot insert orders directly. Reservations run through
`reserve_community_card_spaces`, lock the selected rows, and snapshot the sum of
each selected placement's price minus discount.

## Deployment

Apply migrations in repository order:

```bash
npx supabase db push
```

For a linked project, review the migration plan before confirming the push.
PostgREST receives a schema reload notification in each corrective migration.

## Print limitations

Print preview is deterministic browser rendering from the shared fixed layout.
For the 9x12 format it can show the verified EDDM production proof geometry: a
12.25x9.25-inch bleed sheet, a 12x9-inch trim, and a 0.125-inch safe inset. The
proof guides are editor-only and are hidden automatically when printing.

This is not yet a commercial press-ready export. Crop/registration marks, CMYK
conversion, embedded-font verification, source-art DPI validation, and a
production PDF pipeline are not implemented.
